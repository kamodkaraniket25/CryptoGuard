# CryptoGuard API documentation

Base URL for local development: `http://127.0.0.1:8000`

Interactive documentation generated by FastAPI: `http://127.0.0.1:8000/docs`

The product title in that documentation is **CryptoGuard**.

Successful verification responses share this shape:

```json
{
  "product": "CryptoGuard",
  "full_title": "CryptoGuard — Cryptographic Integrity and Software Supply Chain Verification Platform",
  "operation_id": "uuid",
  "operation_type": "hash_verify",
  "status": "success",
  "algorithm": "SHA-256",
  "created_at": "2026-10-17T12:00:00Z",
  "duration_ms": 4,
  "result": {},
  "limitations": []
}
```

`status` is one of `success`, `failed`, `warning`, or `not_verified`. Feature-specific verdicts such as `MATCH` or `SIGNATURE_VALID` are inside `result`.

## Status codes

| Code | Meaning |
| --- | --- |
| 200 | The operation finished and returned a structured result. An external source error can still be HTTP 200 when the application records that the source failed. |
| 400 | The input is invalid, such as a bad digest, malformed key, or unreadable manifest. |
| 404 | The history record does not exist. |
| 409 | An NVD lookup was requested while `NVD_ENABLED` is false. |
| 413 | The upload or JSON body exceeds the configured limit. |
| 422 | A JSON field failed schema validation. The response does not echo the submitted body. |
| 500 | An unexpected server error. The response does not include a stack trace. |
| 503 | The database health check failed. |

## Endpoints

### Platform

`GET /api/health`

```bash
curl http://127.0.0.1:8000/api/health
```

`GET /api/dashboard/stats`

Returns counts from `verification_records`, unique advisory identifiers, 14 days of activity, and the latest source-check status.

### Integrity

`POST /api/integrity/hash` with multipart field `file`.

`POST /api/integrity/verify` with multipart fields `file` and `reference_digest`.

```bash
curl -F "file=@sample_data/package.json" -F "reference_digest=0123abcd..." http://127.0.0.1:8000/api/integrity/verify
```

`result.verdict` is `MATCH`, `MISMATCH`, or `NOT VERIFIED`.

### HMAC

`POST /api/hmac/generate`

```bash
curl -H "Content-Type: application/json" -d "{\"message\":\"hello\"}" http://127.0.0.1:8000/api/hmac/generate
```

Omit `secret` to generate one with `secrets.token_hex(32)`. The response includes the secret and tag. The database record stores only the message length.

`POST /api/hmac/verify` with `message`, `secret`, and `tag`. `result.verdict` is `VALID` or `INVALID`.

### Signatures

`POST /api/signatures/keygen`

`POST /api/signatures/sign` with `message` and `private_key_pem`.

`POST /api/signatures/verify` with `message`, `public_key_pem`, and `signature`.

The signature is base64. The signed bytes are the exact UTF-8 encoding of `message`.

### Provenance

`POST /api/provenance/sign` with JSON `record` and `private_key_pem`.

`POST /api/provenance/verify` as multipart: `record_json`, optional `public_key_pem`, optional `artifact`.

Result fields:

- `record_status`: `STRUCTURALLY_VALID` or `INCOMPLETE_RECORD`
- `digest_status`: `DIGEST_MATCH`, `DIGEST_MISMATCH`, or `NOT_VERIFIED`
- `signature_status`: `SIGNATURE_VALID`, `SIGNATURE_INVALID`, or `NOT_VERIFIED`

The signed bytes are canonical JSON. See the canonicalization rule returned in the response. It is also described in the README.

### Dependencies and vulnerabilities

`POST /api/dependencies/scan` with multipart `file`, `manifest_format` (`auto`, `npm`, or `pypi`), `refresh`, and `include_nvd`.

`POST /api/vulnerabilities/query`

```json
{
  "name": "lodash",
  "ecosystem": "npm",
  "version": "4.17.20",
  "refresh": false,
  "include_nvd": false
}
```

`POST /api/vulnerabilities/batch` with `packages` (name, ecosystem, version) and `refresh`.

`POST /api/vulnerabilities/nvd` with `cve_id` and `refresh`. Returns 409 when NVD lookups are disabled.

`DELETE /api/vulnerabilities/cache` deletes cached OSV and NVD responses from SQLite.

### Sources

`GET /api/sources` returns the catalog plus the latest check, or `NOT CHECKED`.

`GET /api/sources/status` returns only the status summary.

`POST /api/sources/check` with `{"sources": ["osv", "nvd", "cyclonedx"]}`. An empty list checks all three.

### SBOM

`POST /api/sbom/generate` with multipart `file` and `manifest_format`.

`result.bom` is CycloneDX JSON. `result.valid` reports validation against the vendored 1.7 schema.

### History

`GET /api/history?operation_type=&status=&date_from=YYYY-MM-DD&date_to=YYYY-MM-DD&limit=20&offset=0`

`GET /api/history/export` returns CSV.

`GET /api/history/{operation_id}` returns one sanitized report.

`DELETE /api/history/{operation_id}` deletes that row.

Route order registers `/api/history/export` before `/api/history/{operation_id}` so the word `export` is not treated as an id.
